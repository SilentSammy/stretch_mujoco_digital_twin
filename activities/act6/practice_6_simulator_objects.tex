This guide explains how to configure the Stretch simulator's scene. These
settings only affect simulation; the same robot-control scripts continue to
work on the physical robot.

\section{Getting Started}

Update the repository before running a scenario:

\begin{lstlisting}[language=bash]
git pull
git submodule update --init --recursive
uv sync
\end{lstlisting}

All scene settings live in the root-level \texttt{sim\_config.py}. Select an
included scenario with its final line, then restart the simulated robot:

\begin{lstlisting}[language=Python]
CONFIG = _CUBES
\end{lstlisting}

Start by trying the included scenarios and exploring each scene with normal
teleop controls.

\section{The \texttt{SimConfig} Object}

Every scenario is a \texttt{SimConfig}. Its most useful fields are:

\begin{itemize}
    \item \texttt{objects}: meshes, cubes, and ArUco cubes to add to the scene.
    \item \texttt{robot\_pose}: optional initial position and quaternion for the robot.
    \item \texttt{robocasa}: enables a generated kitchen and selects its task,
    layout, and style.
    \item \texttt{scene}: optional custom MuJoCo scene file. Leave it unset to
    use the default table scene.
    \item \texttt{headless}, \texttt{show\_viewer\_ui}, \texttt{camera\_rate},
    and \texttt{timestep}: viewer, camera, and simulation settings.
\end{itemize}

\section{Objects and Physics}

\texttt{MeshObject.from\_folder()} imports an OBJ mesh and, when present, its
\texttt{texture.png}. \texttt{Cube} creates a box. Its \texttt{texture} can
be \texttt{None}, a PNG path, or a NumPy image. The supplied
\texttt{cube\_texture.png} has six square faces arranged as:

\begin{center}
\begin{tabular}{ccc}
red $+Y$ & green $-Y$ & blue $-X$ \\
yellow $+X$ & magenta $+Z$ & cyan $-Z$
\end{tabular}
\end{center}

\texttt{ArucoCube} inherits from \texttt{Cube} and generates an ArUco texture.
Set \texttt{marker\_faces=1} for a marker on the local top face, or
\texttt{marker\_faces=6} to repeat it on every face.

\begin{center}
\begin{tabular}{lll}
\toprule
\textbf{Option} & \textbf{Values} & \textbf{Meaning} \\
\midrule
\texttt{physics} & \texttt{dynamic} & Responds to forces; movable in object mode. \\
& \texttt{kinematic} & Movable in object mode; unaffected by forces. \\
& \texttt{fixed} & Anchored to the world; unavailable in object mode. \\
\texttt{gravity} & \texttt{True}/\texttt{False} & Enables or compensates gravity for dynamic objects. \\
\texttt{collision} & \texttt{True}/\texttt{False} & Makes an object solid or lets bodies pass through it. \\
\bottomrule
\end{tabular}
\end{center}

The \texttt{\_CUBES} scenario is a compact comparison of these combinations.
It is the best place to experiment with the settings.

\section{Changing the Robot Start Pose}

\begin{lstlisting}[language=Python]
RobotPose(
    position=(0.5, 0.0, 0.0),
    orientation=(0.7071, 0.0, 0.0, 0.7071),
)
\end{lstlisting}

Position uses world metres. Orientation is a quaternion in \texttt{(w, x, y, z)}
order. The default pose is \texttt{(0, 0, 0)} with identity orientation
\texttt{(1, 0, 0, 0)}.

\section{RoboCasa Environments}

Set \texttt{robocasa.enabled=True} to replace the default table scene with a
generated RoboCasa kitchen. \texttt{task} selects the kitchen activity, while
\texttt{layout} and \texttt{style} choose its geometry and appearance. Imported
objects work in RoboCasa exactly as they do in the default scene.

\begin{lstlisting}[language=Python]
SimConfig(
    robocasa=RoboCasaConfig(
        enabled=True,
        task="PnPCounterToCab",
        layout=0,
        style=0,
    ),
    objects=[...],
)
\end{lstlisting}

\section{Interactive Object Controls}

Scenes with dynamic or kinematic objects automatically enable object controls.
Press \texttt{T} or gamepad START to enter object mode; normal teleop input is
temporarily hidden. Press \texttt{T} again to return to robot control and print
the changed objects' reusable poses.

\begin{center}
\begin{tabular}{lll}
\toprule
\textbf{Keyboard} & \textbf{Gamepad} & \textbf{Action} \\
\midrule
\texttt{M} / \texttt{N} & RB / LB & Select next / previous object \\
\texttt{W} / \texttt{S} & Left stick Y & World $+Y$ / $-Y$ \\
\texttt{D} / \texttt{A} & Left stick X & World $+X$ / $-X$ \\
\texttt{Z} / \texttt{X} & Right stick Y & World $+Z$ / $-Z$ \\
\texttt{U/O}, \texttt{I/K}, \texttt{J/L} & LT + sticks & Roll, pitch, yaw \\
\texttt{G} / \texttt{F} & Y / B & Disable / enable gravity \\
\bottomrule
\end{tabular}
\end{center}

\section{Creating Your Own Scene}

Copy an included \texttt{SimConfig}, rename it, and select it with
\texttt{CONFIG}. Give each object a unique \texttt{name}, then set its
\texttt{position}, \texttt{size} or \texttt{scale}, and the physics options
that differ from their defaults. Use object controls to place objects visually;
leaving object mode prints a pose that can be copied into
\texttt{sim\_config.py} for the next run.
